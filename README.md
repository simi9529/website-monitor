# Website monitor

동아대 게시판, 유튜브 커뮤니티와 로그인 필요한 이화이언
<https://ewhaian.com/life/66>의 새 글을 이메일로 알립니다.

동아대 Canvas의 현재 수강 강의 공지사항과 받은 대화메시지도 확인합니다.
두 영역 중 하나에만 새 항목이 생겨도 알리고, 같은 대화에 답장이 여러 개 오면
각 메시지 링크를 한 메일에 모두 담습니다. 본인이 보낸 메시지는 제외합니다.

## 갤럭시 크롬 푸시 알림

구독 페이지: **<https://simi9529.github.io/website-monitor/>**

새 앱 설치 없이 Android Chrome의 웹 푸시로 받습니다. **새 글 하나당 알림 하나**를
보내므로 새 글이 3개면 알림도 3개입니다. 한 글·메시지 안에 링크가 여러 개라면
같은 알림에 모두 담고, 알림을 누르면 그 글의 링크 목록을 보여줍니다. 링크가
하나면 바로 이동합니다. 큰 글은 압축하며 압축 후에도 푸시 크기 한도를 넘으면
링크를 누락하거나 글을 나누지 않고 발송 실패로 처리해 기준을 유지합니다. Chrome·Android가
알림을 묶어 표시할 수 있으며, 실제 팝업 표시는 폰의 알림·절전 설정을 따릅니다.
모니터링 간격은 기존 Actions 예약 주기이며 사이트를 실시간 감시하는 기능은 아닙니다.
동아대 공개 게시판·유튜브도 조회된 목록의 새 글들을 각각 전송합니다. 공개 게시판은
현재 목록 범위를 확인하며, 유튜브에서 이전 기준 글을 찾지 못하면 기준을 유지하고
로그에 표시합니다. 페이지 밖으로 밀린 오래된 미발송 글의 전체 수집은 별도 확인이 필요합니다.

연결 방법:

1. 폰 Chrome에서 구독 페이지를 열고 **알림 받기 → 허용**을 누릅니다.
2. **구독 정보 복사**를 눌러 GitHub Actions Secret `WEB_PUSH_SUBSCRIPTIONS`에 저장합니다.
3. 구독 페이지의 공개키와 짝인 비밀키 파일 내용은 Secret `VAPID_PRIVATE_KEY`에 저장합니다.
   비밀키·구독 정보는 채팅이나 공개 코드·이슈에 올리지 마세요.
4. **Actions → Site Monitor → Run workflow → `test_push`**만 체크해 실제 폰 수신을 확인합니다.
   이 시험은 학교 로그인이나 이메일 발송 없이 실행합니다. 페이지의 로컬 표시 시험은
   폰 알림 권한만 확인하며 실제 서버 발송 성공을 뜻하지 않습니다.

두 Secret이 모두 등록되면 다음 모니터링부터 **이메일 대신 크롬 푸시**로 자동 전환합니다.
GitHub Variables의 `NOTIFICATION_CHANNELS`를 `email`, `push`, `email,push`로 설정해
선택할 수도 있습니다. 기본값 `auto`는 두 푸시 Secret이 없으면 기존 이메일을 유지합니다.
잘못된 키나 만료된 구독으로 발송이 실패하면 해당 게시글 기준을 갱신하지 않고
다음 회차에 재시도합니다. 두 채널을 함께 쓰는 경우 일부 성공 기록은 내용 없는
해시·채널명만 상태 파일에 남겨 이미 성공한 채널의 중복 발송을 줄입니다.

구독 페이지는 GitHub Pages의 `main` 브랜치 `/docs` 폴더를 HTTPS로 게시합니다.
공개 페이지에는 공개키만 포함되며, 구독 정보는 사용자가 복사하기 전까지 기기에
머뭅니다. 서버에 계정·학교 로그인 쿠키·구독 정보 수집 API를 두지 않습니다.
기존 Chrome 구독을 삭제하거나 사이트 알림 권한을 초기화했다면 새 구독 정보를
Secret에 다시 저장해야 합니다. 여러 기기는 구독 JSON 객체들을 배열로 저장합니다.

새 키가 필요한 경우(키를 바꾸면 모든 기기를 재등록해야 합니다):

```sh
python tools/setup_web_push.py --private-key /저장소밖경로/vapid-private.txt
```

생성된 `docs/config.json`만 공개하며 비밀키 파일은 저장소에 넣지 않습니다.
현재 배포된 공개키에 대응하는 기존 비밀키를 재사용하는 것이 기본입니다.
웹 푸시는 표준 암호화와 VAPID 서명을 사용하며, Chrome 푸시 서비스에는 암호문을
보냅니다. 실제 폰 수신은 사용자가 구독한 뒤 별도로 확인해야 합니다.

## 실행 설정

기존 `.github/workflows/dongaupdate.yml`이 5분마다 `dongaupdate.py`를 실행합니다.
GitHub 저장소의 **Settings → Secrets and variables → Actions → Secrets**에
다음 값을 등록하세요. 클라우드 환경의 변수는 GitHub Actions로 자동 복사되지 않습니다.

| 이름 | 값 |
| --- | --- |
| `FROM_EMAIL` | 알림을 보내는 Gmail 주소 |
| `TO_EMAIL` | 알림을 받을 이메일 주소 |
| `APP_PASSWORD` | 발신 Gmail 계정의 16자리 앱 비밀번호 |
| `EWHA_ID` | 해당 게시판을 열람할 수 있는 이화이언 계정 아이디 |
| `EWHA_PW` | 이화이언 계정 비밀번호 |
| `CANVAS_ID` | 동아대 학교 통합 로그인 학번·아이디 |
| `CANVAS_PW` | 학교 통합 로그인 비밀번호 |

이화이언 계정은 아이디/비밀번호로 로그인합니다. 로그인 결과의 토큰은 실행 중
메모리에서만 사용하며 파일에 저장하지 않습니다. 계정 정보가 없거나 로그인에
실패하면 이화이언 확인만 건너뛰고 기존 사이트 모니터링을 계속합니다.
비밀번호나 토큰을 코드·로그·채팅에 넣지 마세요.

이화이언은 **첫 실행에 최신 글 번호만 기록**하고, 이후 실행부터 새 글을 알립니다.
한 회차 사이에 여러 글이 올라오면 **모든 새 글의 제목과 링크를 메일 한 통에**
오래된 글부터 담아 발송합니다. 새 글이 2개면 메일에 두 링크가 모두 포함됩니다.
발송에 실패하면 상태를 갱신하지 않고 다음 실행에 모두 재시도합니다.
`titles.json`에 마지막으로 알린 글 번호를 저장하므로
기존 Actions의 상태 커밋 단계가 필요합니다. 작업 간격은 GitHub 스케줄 상황에 따라
5분보다 길어질 수 있습니다.

로컬에서는 Python 3.11 가상환경에 의존성을 설치한 뒤, 위 환경변수를 안전하게
설정하고 저장소 디렉터리에서 실행하세요. 이 명령은 실제 이메일을 보낼 수 있습니다.

```sh
python -m pip install -r requirements.txt
python dongaupdate.py
```

실제 로그인과 메일 발송을 확인하려면 같은 환경변수를 설정한 뒤 다음 명령을
실행하세요. **현재 최신 글의 제목과 링크를 담은 실제 메일 한 통을 발송**합니다.
메일 서버가 수신을 수락한 뒤, 아직 모니터링 시작 기준이 없다면 해당 글 번호를
기록합니다. 기존 모니터링 기준이 있으면 미발송 글을 건너뛰지 않도록 유지합니다.

```sh
python dongaupdate.py --send-latest-ewhaian
```

이 클라우드에서 Gmail SMTP 연결이 되지 않으면 GitHub Actions 실행 환경에서
시험 발송할 수 있습니다. 변경사항을 GitHub에 반영하고 위 다섯 값을 Actions
Secrets에 등록한 뒤, **Actions → Site Monitor → Run workflow**에서
`send_latest_ewhaian`을 체크해 실행하세요. 체크하지 않은 수동 실행과 예약 실행은
평소처럼 모든 사이트를 확인합니다. 클라우드에 저장한 인증 정보는 Actions로
자동 전달되지 않습니다. Actions에서의 실제 SMTP 연결·메일 발송 성공 여부는
해당 실행 로그로 확인해야 합니다.

### Actions에서 종료 코드 2로 실패할 때

`--send-latest-ewhaian` 시험 발송은 다섯 환경변수 중 하나라도 비어 있으면
종료 코드 2로 중단합니다. **Validate Actions secrets** 단계와 실행 Summary에
누락된 이름만 표시하며, 비밀번호나 이메일 값은 출력하지 않습니다.

해당 이름을 GitHub 저장소 **Settings → Secrets and variables → Actions → Secrets**의
Repository secret으로 등록하세요. 클라우드 환경 설정에만 등록한 값이나 GitHub의
별도 **Variables** 탭 값은 이 워크플로의 `secrets.*`에 전달되지 않습니다.
등록 후 **Re-run jobs**로 재시도할 수 있습니다. 워크플로 코드 자체가 바뀌었다면
이전 실행을 재실행하는 대신 `main`에서 **Run workflow**로 새로 실행하세요.

워크플로는 Ubuntu 24.04, Python 3.11과 Node.js 24 기반 액션을 사용합니다.

## 동아대 Canvas 공지·대화 알림

Canvas용 두 값을 **GitHub Actions Secrets**에 추가하면 기존 5분 주기 작업에서
함께 실행됩니다. 값이 없으면 Canvas만 건너뜁니다. 클라우드에서 실제 로그인을
검증하려면 클라우드 환경 설정에도 같은 이름으로 값을 따로 등록하세요.

통합 로그인은 `canvas.donga.ac.kr` → `eclass.donga.ac.kr` →
`dxsso.donga.ac.kr` → `login.donga.ac.kr`의 학교 로그인 화면을 거칩니다.
Playwright가 학교 화면의 정상 로그인 절차를 실행하고, Canvas 인증 확인 후
세션 쿠키를 메모리에서만 사용합니다. TLS 인증서 검증은 유지하며 추가 인증이나
CAPTCHA를 우회하지 않습니다. 클라우드 프록시 환경에서는 플랫폼 CA를 신뢰하는
Playwright HTTP 클라이언트로 브라우저 리소스를 검증해 가져옵니다.
학교 오류 9002(중복 로그인)는 사용자 동의에 따라 자동 수락합니다. 예약 실행은
`CANVAS_REPLACE_SESSION=true`로 설정되어 기존 PC·휴대폰의 포털 연결이 종료될 수
있습니다. 로컬에서도 이 환경변수를 설정하면 동일하게 동작합니다. 이 동작을 끄려면
워크플로의 값을 `false`로 바꾸세요. 다른 확인창이나 추가 인증은 자동 수락하지 않습니다.

첫 확인은 기존 공지·대화를 시작 기준으로 기록하고, 이후부터 새 항목을 알립니다.
대화방 번호뿐 아니라 메시지 번호도 확인하므로 기존 대화의 새 답장을 놓치지
않습니다. 모니터링·시험 발송·이메일 발송은 읽음 상태를 바꾸지 않습니다.
메시지 조회에는 `auto_mark_as_read=false`를 사용합니다. Canvas 홈페이지에서
해당 공지나 대화를 직접 눌러 열면 Canvas의 기본 동작에 따라 읽음 처리됩니다.
대화 알림 메일에는 해당 메시지 본문의 웹 링크를 중복 없이 모두 포함합니다.
HTML 링크와 일반 URL을 지원하며, 본문에 링크가 없을 때만 대화방 주소를 사용합니다.
공지와 대화는 각각 조회하므로 한쪽 실패가 다른 쪽 알림을 막지 않습니다.
발송에 실패하면 해당 알림 기준을 갱신하지 않아 다음 회차에 재시도합니다.
상태 파일에는 항목 번호와 시각만 저장하고, 제목·메시지 본문·계정 정보는 저장하지
않습니다. 최초 공지 확인 범위는 최근 180일, 이후에는 마지막 확인 이후입니다.

시험 발송은 **Actions → Site Monitor → Run workflow → `test_canvas` 체크**로
실행하세요. 접근 가능한 최신 공지 1개와 최신 수신 메시지 1개의 링크를 최대 두 개
담은 실제 시험 메일을 보냅니다. 이화이언 시험 옵션과 동시에 선택할 수 없습니다.
정상 예약 실행의 제목에는 ‘시험 발송’이 붙지 않습니다.

로컬에서는 다음과 같이 실행할 수 있습니다. 실제 메일이 발송될 수 있습니다.

```sh
python -m playwright install --with-deps chromium
python dongaupdate.py --test-canvas
```

현재 수강 중인 학생 강의만 공지 대상으로 조회합니다. 추가 인증이 매번 필요한
학교 계정은 무인 로그인이 완료되지 않을 수 있으므로 실행 로그를 확인하세요.

이화이언은 사이트가 사용하는 로그인·목록 조회 API를 사용하므로 브라우저 설치가
필요하지 않습니다. 사이트 API가 변경되거나 계정의 열람 권한이 없으면 로그를
확인하세요. CAPTCHA나 추가 인증을 우회하지 않습니다.

외부 계정·메일 발송 없이 기능을 검증하려면:

```sh
python -m unittest discover -s tests -v
```
